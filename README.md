# MT5 AI-Agent

Рабочая пара по умолчанию — **AUDCAD**. Контролируемый торговый агент на Python через
официальный модуль **`MetaTrader5`**:
ML-модель даёт сигнал, локальная LLM фильтрует новостной фон, риск-модуль решает,
можно ли вообще рисковать деньгами, и только потом уходит заявка в терминал.

Это **не готовый «чудо-бот»**: агент запускается на твоём Windows-ПК или Windows VPS,
подключается к **отдельному** MT5-счёту, работает только с инструментами, которые
ты сам разрешил в конфиге, и по умолчанию **вообще не выходит на реальные деньги**.

```
Данные MT5 → признаки → ML-вероятность → порог → фильтры (сессия, спред, новости)
          → риск-модуль (лимиты + размер позиции) → ордер со SL/TP → учёт и отчёты
```

## С чего начать (Windows)

### 0. Что понадобится

| Что | Зачем | Требования |
|---|---|---|
| Windows 10/11 или Windows VPS | `MetaTrader5` существует только под Windows | 2 ГБ RAM, стабильный интернет |
| Терминал MetaTrader 5 | исполнение ордеров и данные | **ДЕМО-счёт** для начала |
| Python 3.10–3.13 | под него собрано колесо `MetaTrader5` | рекомендую 3.11 или 3.12 |
| Git (по желанию) | обновление кода | не обязательно |

> Почему Windows VPS, а не домашний ПК, спящий по ночам: агенту нужен постоянный
> доступ к терминалу. Но **начинать можно и на домашнем ПК** — в режиме `shadow`
> агент всё равно не торгует.

### 1. Установка

Скачай проект и в PowerShell (не от администратора) выполни:

```powershell
cd путь\к\проекту
powershell -ExecutionPolicy Bypass -File .\scripts\install.ps1
```

Скрипт создаст `.venv`, поставит зависимости (включая `MetaTrader5`) и скопирует
`.env.example` → `.env`.

### 2. Заполни `.env`

Открой `.env` блокнотом и впиши реквизиты **ДЕМО-счёта**:

```ini
MT5_LOGIN=12345678
MT5_PASSWORD=пароль_демо
MT5_SERVER=MetaQuotes-Demo
MT5_TERMINAL_PATH=C:\Program Files\MetaTrader 5\terminal64.exe
```

Пароля от реального счёта в проекте быть не должно. Реальный блок (`MT5_REAL_*`)
заполняется отдельно и только тогда, когда ты осознанно решишь перейти на реал.

### 3. (Необязательно) Посмотри, как агент работает — без MT5

Если хочется понять, что вообще происходит, ещё до настройки терминала:

```powershell
.\.venv\Scripts\python.exe tools\demo_cycle.py --cycles 40 --step 3 --quiet
```

Это полный цикл агента на **виртуальном рынке**: сделки, стопы, лимиты дня, учёт
закрытых позиций, дашборд. Реальное состояние агента при этом не затрагивается —
всё пишется в `state/demo/`. Помни: синтетические цены ничего не говорят о
доходности, это проверка программы.

### 4. Проверь связь

```powershell
.\.venv\Scripts\python.exe -m mt5_agent check
```

Команда покажет: найден ли терминал, демо ли счёт, разрешена ли автоторговля,
какие у инструментов `digits`/`tick_value`/шаг лота, есть ли обученная модель.
Всё помеченное значком ⛔️ нужно исправить **до** запуска торговли.

### 5. Скачай данные и обучи модель

```powershell
# бары + параметры символов с твоего брокера (важно: tick_value у всех разный)
.\.venv\Scripts\python.exe -m mt5_agent fetch --bars 20000 --save-specs

# обучение с честной walk-forward проверкой
.\.venv\Scripts\python.exe -m mt5_agent train --symbol AUDCAD
```

Отчёт появится в `reports/train_AUDCAD_M15.txt`. Смотри не на «AUC на train», а на
**AUC и доходность на отложенном тесте**. Если там ~0.5 — у модели нет преимущества,
и торговать нельзя.

### 6. Бэктест с издержками

```powershell
.\.venv\Scripts\python.exe -m mt5_agent backtest --symbol AUDCAD --days 180
```

Бэктест считает спред, комиссию и проскальзывание, а стоп внутри бара проверяет
**раньше** тейка (худший вариант). В конце — явный вердикт:

* ✅ метрики в норме → можно проверить на демо;
* ⛔️ НЕ ГОДИТСЯ → править гипотезу, а не пороги в конфиге.

### 7. Демо-торговля (1–3 месяца — минимум)

```powershell
# наблюдение без ордеров — полезно, чтобы увидеть, как агент принимает решения
powershell -ExecutionPolicy Bypass -File .\scripts\start_agent.ps1 -Mode shadow

# демо-ордера на ДЕМО-счёте
powershell -ExecutionPolicy Bypass -File .\scripts\start_agent.ps1 -Mode paper
```

Дашборд: `.\.venv\Scripts\python.exe tools\dashboard.py` → http://127.0.0.1:8787

Демо-режим — это не «потерянное время», а единственный способ узнать реальный
спред, проскальзывание и поведение агента на живом рынке.

### 8. Реальный счёт (когда вышел срок демо и есть статистика)

Три независимых барьера нужно снять осознанно:

1. `.env`: заполнить `MT5_REAL_*` и поставить `I_UNDERSTAND_REAL_MONEY_RISK=TRUE`;
2. `config/config.yaml`: `agent.mode: live` и `safety.demo_only: false`;
3. Запуск с флагом: `start_agent.ps1 -Mode live -AllowLive` + подтверждение в консоли.

Правила, которые нельзя обойти: **отдельный счёт**, сумма, которую готов потерять
целиком, лимиты риска в конфиге не меняются «на эмоциях».

## Приложение для ПК (Windows)

Есть настольное приложение: мастер настройки счёта, «быстрый старт» по шагам
(проверка → данные → обучение → бэктест → демо), статус, позиции, журнал и аварийный
стоп — в одном окне. Работает на встроенном `tkinter`, внешних зависимостей нет.

```powershell
# вариант 1: скачать готовый MT5-Agent.exe (Python не нужен) — см. docs/APP.md
# вариант 2: собрать на своём ПК
powershell -ExecutionPolicy Bypass -File .\scripts\build_exe.ps1

# вариант 3: запустить интерфейс на уже установленном Python
powershell -ExecutionPolicy Bypass -File .\scripts\start_gui.ps1
# ярлык на рабочем столе: ...start_gui.ps1 -CreateShortcut
```

Собранный `.exe` двурежимный: без аргументов — окно панели, с флагом `--cli` — обычные
команды агента (`MT5-Agent.exe --cli backtest --symbol AUDCAD --days 180`).
Подробности, скриншоты шагов и ограничения: [`docs/APP.md`](docs/APP.md).

Чего в интерфейсе намеренно нет:

* **кнопки реального счёта** — из окна доступны только `shadow` и `paper`; реал требует
  трёх подтверждений и запускается из консоли (см. `docs/SAFETY.md`);
* **правки лимитов риска в один клик** — лимиты живут в `config.yaml` и применяются
  после перезапуска агента: решение «увеличить риск» не должно приниматься в просадке;
* **собственной логики** — панель только запускает тот же CLI и читает те же файлы
  состояния, что и консоль, поэтому не может разойтись с проверенной логикой.

| Способ | Для чего |
|---|---|
| **Приложение** (`MT5-Agent.exe` / `start_gui.ps1`) | ежедневное управление: статус, запуск, обучение, стоп |
| **Дашборд** (`tools\dashboard.py`) | смотреть с телефона/другого ПК: только чтение, ничего не меняет |
| **CLI** (`python -m mt5_agent ...` / `MT5-Agent.exe --cli ...`) | точный контроль, автоматизация, планировщик, реал |
| **Watchdog** (`watchdog.ps1`) | режим 24/7: следит за heartbeat и поднимает упавшего агента |

## Что агент умеет и что делает по-другому

**ML-модель предсказывает не цену, а событие: «движение вперёд превысит издержки».**
Это превращает задачу из «угадай цену» (чего никто не умеет стабильно) в измеримую
величину: ожидаемую доходность на сделку с учётом спреда и комиссии.

**LLM — фильтр, а не трейдер.** Локальная модель (например, Ollama) читает заголовки
и отвечает строго JSON: `{"risk": 0.8, "block": true, "reason": "..."}`. Её слово
может только запретить вход, но не создать сигнал. Если LLM недоступна — работает
детерминированная эвристика по ключевым событиям (FOMC, NFP, CPI…).

**Риск стоит выше сигнала.** Даже идеальная вероятность 0.95 не создаст заявку, если
пробит дневной лимит, сработала пауза после убытка, включён kill switch или объём
под риск меньше минимального лота брокера (тогда сделка просто отклоняется).

**Всё проверяемо офлайн.** Фичи, метки, размер позиции и бэктест не требуют ни
терминала, ни интернета: `--synthetic` прогоняет обучение и бэктест на выдуманных
данных, `tools/demo_cycle.py` крутит полный цикл агента на виртуальном брокере
(состояние — в `state/demo/`, реальные файлы не трогаются), а 144 теста идут
на любой ОС без Windows и без MT5 — включая дымовые тесты панели управления.

## Команды

| Команда | Что делает |
|---|---|
| `check` | окружение, связь с терминалом, спецификации символов, наличие модели |
| `fetch` | скачать бары в `data/*.csv` и параметры символов в `data/symbol_specs.yaml` |
| `train` | обучить модель (walk-forward, отчёт в `reports/`) |
| `backtest` | честный прогон с издержками и вердиктом GO/NO-GO |
| `run` | торговый цикл: `--mode paper\|shadow\|live`, `--once`, `--dry-run` |
| `status` | что происходит сейчас: счёт, лимиты, позиции, сигналы, блокировки |
| `panel` | открыть приложение (окно панели управления; Windows, встроенный tkinter) |
| `stop` | мягкая остановка: доработать цикл и выйти, позиции не закрываются |
| `kill` | аварийный стоп: агент закроет свои позиции и остановится |
| `unkill` | снять аварийный стоп и сбросить halt |

Примеры:

```powershell
.\.venv\Scripts\python.exe -m mt5_agent run --once --dry-run     # один цикл без ордеров
.\.venv\Scripts\python.exe -m mt5_agent status                   # состояние агента
.\.venv\Scripts\python.exe -m mt5_agent kill --reason "уезжаю"   # аварийный стоп
```

## Риск-модуль: цифры по умолчанию

| Параметр | Значение | Где менять |
|---|---|---|
| Риск на сделку | **0.5%** equity (диапазон 0.25–1%) | `risk.risk_per_trade_pct` |
| Дневной лимит убытка | **-2%** | `risk.max_daily_loss_pct` |
| Недельный лимит | **-5%** | `risk.max_weekly_loss_pct` |
| Общая просадка от пика | **-10%** | `risk.max_drawdown_pct` |
| Максимум позиций | 2 (по 1 на символ) | `risk.max_open_positions` |
| Сделок в день | 6 | `risk.max_daily_trades` |
| Пауза после убытка | 30 минут | `risk.cooldown_after_loss_min` |
| Мартингейл / сетки | **запрещены в коде** | — |
| Стоп-лосс | обязателен всегда, вместе с ордером | — |

Если значения в конфиге выходят за «здравые» пределы (риск > 1%, дневной лимит > 5%,
просадка > 25%) — загрузка конфига падает с ошибкой. Это специально: нельзя
«случайно» поставить риск 10% в пятницу вечером.

## Частые вопросы

**Модель даёт AUC 0.5 и бэктест отрицательный. Что делать?**
Это нормальный результат, а не поломка: большинство простых идей в трейдинге не
работают. Правильные шаги: больше данных (годы, а не месяцы), другие таймфреймы,
другие признаки, другой горизонт, проверка издержек. Неподходящие шаги: понижать
пороги, «подгонять» параметры под историю, увеличивать риск, чтобы «отыграться».

**Как часто переобучать модель?**
По умолчанию раз в 7 дней (`signal.retrain_every_days`). Данные накапливай и
сравнивай метрики: если новая модель хуже — это сигнал, что рынок изменился,
а не повод подкрутить пороги.

**Почему по умолчанию именно AUDCAD и что в нём особенного?**
Это кросс без доллара: валюта прибыли — CAD, поэтому стоимость пункта для долларового
счёта зависит от курса USDCAD, а не равна фиксированному доллару (агент берёт её из
терминала, справочник в `specs.py` — только ориентир для песочницы). Спред шире, чем у
EURUSD, и резко расширяется на ролловере и в пятницу вечером. Ликвидность приходит
двумя волнами, поэтому в конфиге заданы два окна: `00:00–06:00` (Токио/Сидней со
стороны AUD) и `13:00–19:00` (Нью-Йорк со стороны CAD) — «мёртвая зона» между ними
исключена. Проверяется тестами `tests/test_audcad.py`.

**Можно ли добавить свои символы?**
Да: добавь блок в `trading.symbols` с уникальным `magic`, потом `fetch --symbol NEW`
и `train --symbol NEW`. Бэктест считает спецификации из `data/symbol_specs.yaml`,
поэтому их обязательно надо снять с брокера.

**Чем панель отличается от дашборда?**
Панель — это «пульт»: кнопки запуска/остановки, kill switch, обучение и бэктест,
то есть она меняет состояние. Дашборд — витрина только для чтения: его удобно
открыть с телефона, но через него нельзя ничего запустить или остановить.

**Можно ли управлять агентом с телефона?**
Смотреть — да (дашборд). Запускать и останавливать — только безопасными способами:
либо через RDP на VPS, либо ограниченным доступом по сети к панели (не рекомендую
без VPN: пульт умеет включать демо-торговлю). Для телефона практичнее уведомления
в Telegram, которые уже настроены в проекте.

**А если агент «зависнет»?**
Watchdog проверяет `state/heartbeat.txt`. Если файл не обновлялся дольше порога —
процесс считается зависшим и перезапускается. Открытые позиции при этом остаются
защищёнными стоп-лоссами в терминале — SL стоит на стороне брокера, а не в памяти
программы. Это одна из причин, почему стоп обязателен.

**Что реально ограничивает потери?**
Три вещи: (1) стоп-лосс на стороне брокера, (2) лимиты дня/недели/просадки,
которые хранятся на диске и не сбрасываются перезапуском, (3) объём позиции,
посчитанный от риска, а не «на глаз». Всё остальное — вторично.

## Честный дисклеймер

* Это инструмент, а не источник дохода. Никто не может гарантировать прибыль на рынке.
* Прошлые результаты (в том числе бэктест) не предсказывают будущие.
* Используй **отдельный счёт** и только те деньги, которые готов потерять целиком.
* Никогда не давай этому (или любому другому) боту доступ к основному счёту и не
  пересылай пароли в мессенджеры — код работает локально, ему пароль передаётся
  только через твой собственный файл `.env`.
* Мартингейл, сетки, торговля без стоп-лосса и «догон» убытков запрещены в коде
