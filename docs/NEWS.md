# Новостной фильтр и локальная LLM

Здесь описано, как устроен фильтр новостей и как подключить локальную модель. Держи
в голове главное правило: **LLM может только запретить сделку, но не создать её.**
Сигнал приходит исключительно из ML-модели по котировкам; новости способны лишь
остановить вход в плохой момент.

## Конвейер фильтра

```
state/headlines.txt  ─┐
                      ├─→ сбор заголовков → эвристика (всегда) → опц. LLM → риск 0..1
HTTP-источник (JSON) ─┘                                    │
                                                           ▼
                    риск ≥ negative_block_threshold (0.6) → входы ЗАБЛОКИРОВАНЫ
```

Результат сохраняется в `state/sentiment_cache.json` на `cache_minutes` минут, чтобы
агент не запрашивал внешние источники на каждом цикле (60 секунд). События фильтра
пишутся в `logs/events.jsonl` (`kind: "sentiment"`) — по ним видно, что именно
заблокировало вход.

## Уровень 1: эвристика (работает всегда)

Детерминированный словарь в `src/mt5_agent/sentiment.py`:

* **События высокой важности** (`HIGH_IMPACT_EVENTS`): `fomc`, `rate decision`,
  `nonfarm payroll`, `cpi`, `ppi`, `gdp`, `ecb decision`, `powell speaks`, … Веса 0.6–0.9.
* **Негативные термины** (`NEGATIVE_TERMS`): `war`, `default`, `bank run`, `crash`,
  `sanctions`, `downgrade`, … Веса 0.15–0.5.
* **Позитивные термины** (`POSITIVE_TERMS`): `dovish`, `rate cut`, `ceasefire`,
  `soft landing`, … Веса 0.15–0.35.

Итоговый риск — «вероятностное ИЛИ» совпавших весов: несколько сигналов вместе
весомее одного. Одна «красная» новость перевешивает десять нейтральных — так и должно
быть, ведь мы защищаемся от хвостовых событий.

Проверить, как это работает, можно без агента:

```powershell
.\.venv\Scripts\python.exe -c "from mt5_agent.sentiment import score_headlines; print(score_headlines(['FOMC rate decision tonight']))"
# → (0.9, -0.9, ['fomc', 'rate decision'])
```

### Как вести `state/headlines.txt`

Простой текстовый файл, по одной строке на заголовок. Строки, начинающиеся с `#`,
игнорируются:

```
# Обновляй вручную или скриптом из экономического календаря
FOMC rate decision at 19:00 UTC
US CPI data expected to surprise to the upside
```

Практический вариант без API: утром копируешь в файл 5–10 заголовков из календаря
важных событий, вечером очищаешь. Этого достаточно, чтобы не входить в моменты
публикаций.

## Уровень 2: локальная LLM (опционально)

Зачем: эвристика ловит ключевые слова, LLM понимает формулировку («банковский сектор
под давлением из-за оттока депозитов»). При этом модель работает **локально** — ни
заголовки, ни данные счёта никуда не уходят.

### Установка (пример с Ollama, Windows)

1. Скачай Ollama для Windows: <https://ollama.com/download>
2. В PowerShell подтяни модель:

```powershell
ollama pull gpt-oss:20b     # или llama3.1:8b, qwen2.5:14b — что потянет VPS
ollama serve                 # обычно уже запущен как служба, порт 11434
```

3. Проверь, что OpenAI-совместимый эндпоинт отвечает:

```powershell
curl http://localhost:11434/v1/models
```

4. Включи фильтр в `config/config.yaml`:

```yaml
sentiment:
  enabled: true
  provider: "headlines"
  headlines_file: "state/headlines.txt"
  negative_block_threshold: 0.6
  llm:
    enabled: true
    base_url: "http://localhost:11434/v1"
    model: "gpt-oss:20b"
    api_key_env: "LLM_API_KEY"   # для локального сервера можно оставить пустым
    timeout_sec: 20
```

Если у модели на VPS мало памяти, возьми модель поменьше (`llama3.2:3b`,
`qwen2.5:7b`): фильтру не нужен «ум», нужна аккуратная классификация.

### Контракт ответа LLM

Агент отправляет системный промпт и список заголовков, ожидая строгий JSON:

```json
{"risk": 0.8, "block": true, "reason": "выход данных по инфляции в течение часа"}
```

Правила обработки:

* `risk` приводится в диапазон 0..1; итоговый риск = **максимум** из эвристики и LLM
  (модель не может понизить оценку риска);
* `block: true` гарантированно поднимает риск до порога блокировки;
* любой ответ, не содержащий JSON или поля `risk`, **игнорируется** — работает
  эвристика;
* недоступность модели (таймаут, сервер выключен) никогда не роняет агент: в логе
  появляется предупреждение, торговля продолжается на эвристике.

### Тестирование

```powershell
# Проверить связь с локальной LLM, не запуская торговлю
.\.venv\Scripts\python.exe -c @"
from mt5_agent.config import LLMConfig
from mt5_agent.sentiment import llm_verdict
cfg = LLMConfig(enabled=True, base_url='http://localhost:11434/v1', model='gpt-oss:20b')
print(llm_verdict(['FOMC rate decision tonight', 'Markets calm'], cfg))
"@
```

Ожидаемый ответ — словарь вида `{'risk': 0.8, 'block': True, 'reason': 'FOMC tonight'}`.

## Чего фильтр НЕ делает

* **Не предсказывает цену.** Никаких «GPT говорит, что EURUSD пойдёт вверх».
* **Не влияет на размер позиции.** Даже при позитивном фоне риск на сделку не
  увеличивается — только слегка повышается порог вероятности (`positive_boost`).
* **Не работает без сигнала.** Если модели нет или вероятность в «серой зоне»,
  фильтр вообще не влияет на решение — сделки не будет.
* **Не является защитой от всего.** Внезапная новость без заголовков (или с
  заголовком мимо словаря) останется незамеченной. Именно поэтому стоп-лосс
  обязателен и стоит на стороне брокера.

## Если решишь подключать платный новостной API

Подойдёт любой источник, отдающий JSON со списком заголовков. Укажи:

```yaml
sentiment:
  enabled: true
  provider: "http_json"
  url: "https://example.com/api/headlines?symbol=EURUSD"
  api_key_env: "NEWS_API_KEY"     # имя переменной в .env, не сам ключ
  fetch_timeout_sec: 10
```

Поддерживаются форматы ответа: `{"headlines": [...]}`, `{"items": [...]}`,
`{"news": [...]}`, `{"titles": [...]}` или просто список строк. Если формат другой —
добавь разбор в `SentimentFilter._headlines_from_http` (это 5 строк кода) и напиши
на него тест.
