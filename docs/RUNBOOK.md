# Журнал эксплуатации (RUNBOOK)

Практические процедуры: как развернуть на VPS, как понять, что всё живо, что делать
при типовых сбоях. Все команды выполняются из папки проекта в PowerShell.

---

## 1. Первый день: развёртывание на Windows VPS

**Почему VPS.** Агент должен просыпаться каждые 60 секунд и держать подключение к
терминалу. Домашний ПК, который уходит в сон, для этого не годится. Минимальной
конфигурации (2 vCPU, 2–4 ГБ RAM, Windows Server 2019/2022) достаточно: серьёзных
вычислений агент не делает.

Порядок:

1. **Подключись по RDP**, убедись, что системные часы синхронизированы (важно:
   весь код работает в UTC, а MT5 отдаёт своё время сервера).
2. **Установи терминал MetaTrader 5.** Запусти его, войди в **ДЕМО-счёт**,
   включи кнопку «Автоторговля» (**AutoTrading**). Проверь, что в «Обзоре рынка»
   есть нужные символы (EURUSD и т.п.).
3. **Скопируй проект** на VPS (git clone или архив) в папку вида `C:\mt5-agent`.
4. Запусти установку: `powershell -ExecutionPolicy Bypass -File .\scripts\install.ps1`
5. Заполни `.env` реквизитами демо-счёта.
6. Проверь: `.\.venv\Scripts\python.exe -m mt5_agent check` — все пункты должны быть ✅.
7. Скачай данные: `... fetch --bars 20000 --save-specs`
8. Обучи модель: `... train --symbol EURUSD`
9. Бэктест: `... backtest --symbol EURUSD --days 180` → смотри вердикт.
10. Регистрация задач планировщика (запуск от администратора):

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\register_tasks.ps1 -Mode paper
```

Создаются две задачи: `MT5-Agent-Watchdog` (каждые 5 минут проверяет heartbeat и
при необходимости перезапускает агента) и `MT5-Agent-Dashboard` (дашборд на
`http://127.0.0.1:8787`).

**Важно про RDP:** при отключении сессии сеанс Windows продолжает жить, но убедись,
что в настройках электропитания не включён быстрый сон, а терминал MT5 остаётся
запущенным. Проверь это через сутки после тестового запуска — это самый частый
источник «агент не торговал всю ночь».

## 2. Ежедневная проверка (2 минуты)

```powershell
.\.venv\Scripts\python.exe -m mt5_agent status
```

Что должно быть в выводе:

| Поле | Норма | Тревога |
|---|---|---|
| «Агент работает» | heartbeat свежий (секунды-минуты) | «НЕ ОТВЕЧАЕТ» → смотри п. 4 |
| Kill switch | снят | АКТИВЕН → разобраться, кто/почему включил |
| Halt | нет | есть → в причине указано, какой лимит сработал |
| Позиции | не больше `max_open_positions` | больше → срочно проверить magic-номера |
| Ошибки последнего цикла | пусто | повторяются → смотри `logs/agent.log` |

Журналы:

* `logs/agent.log` — основной лог (ротация 5 МБ × 5);
* `logs/events.jsonl` — структурированные события (сигналы, ордера, закрытия);
* `logs/console.log` — вывод из `start_agent.ps1`;
* `reports/last_cycle.txt` — человекочитаемый отчёт последнего цикла.

## 3. Еженедельная сверка (15 минут)

Цель — поймать расхождение между ожиданием и реальностью **до** того, как оно
станет дорогим.

1. **Сделки:** сравни количество сделок за неделю в терминале (История) с
   `state/agent_state.json` → `weekly.trades_closed`.
2. **Проскальзывание:** в `logs/events.jsonl` найди события `slippage`. Если их
   много или значения близки к `execution.max_slippage_points` — увеличь спред в
   бэктесте и проверь ликвидность в часы работы.
3. **Издержки:** в терминале посмотри суммарную комиссию и свопы за неделю.
   Сравни с `costs_total` из отчёта бэктеста (в пересчёте на число сделок).
4. **Расхождение с бэктестом:** в отчёте бэктеста есть блок
   `compare_to_reality`-логика (используется при разборе): факт на 50% и хуже от
   ожидания — сигнал, что модель/исполнение работают не так, как в тесте.
5. **Переобучение модели:** раз в 7 дней.

```powershell
.\.venv\Scripts\python.exe -m mt5_agent fetch --bars 20000 --save-specs
.\.venv\Scripts\python.exe -m mt5_agent train --symbol EURUSD
.\.venv\Scripts\python.exe -m mt5_agent backtest --symbol EURUSD --days 180
```

Сравни новый AUC на отложенном тесте с прошлым. Резкое падение (например, 0.55 → 0.50)
— повод **остановить торговлю и разобраться**, а не «переждать».

## 4. Типовые инциденты

### 4.1 Агент не отвечает (heartbeat старый)

```powershell
# 1. Кто вообще запущен
Get-CimInstance Win32_Process -Filter "Name = 'python.exe'" | Select-Object ProcessId, CommandLine

# 2. Последние строки логов
Get-Content .\logs\agent.log -Tail 50
Get-Content .\logs\console.log -Tail 30
```

Дальше:

* если процесса нет — запусти вручную: `.\scripts\start_agent.ps1 -Mode paper`;
* если процесс есть, но висит — пусть watchdog завершит его и перезапустит:
  `powershell -ExecutionPolicy Bypass -File .\scripts\watchdog.ps1`;
* если в логах «терминал не подключён» — открой MT5, проверь интернет и вход в счёт.

Открытые позиции при этом **остаются защищёнными**: стоп-лоссы стоят на стороне
брокера, а не в программе.

### 4.2 Терминал обновился / брокер сменил спецификацию символа

`tick_value`, `point`, `stops_level` могут измениться после обновления терминала или
смены брокерского сервера. Признак: сделки отклоняются с retcode `10016` (неверные
стопы) или объём систематически «не тот».

Лечение:

```powershell
.\.venv\Scripts\python.exe -m mt5_agent fetch --save-specs
.\.venv\Scripts\python.exe -m mt5_agent backtest --symbol EURUSD --days 180
```

`--save-specs` обновляет `data/symbol_specs.yaml` — именно оттуда бэктест берёт
стоимость пункта. Никогда не правь эти числа руками «на глазок».

### 4.3 Сработал дневной/недельный лимит

Это не сбой, а работа защиты. Что делать: **ничего**. Не отключать лимит, не
перезапускать агента «чтобы сбросить» (не поможет — состояние хранится на диске).
Разбери журнал: список блокировок в `status` покажет, какой именно лимит сработал.
Если лимит срабатывает часто — проблема в стратегии, а не в лимите.

### 4.4 На счёте появились посторонние позиции

Агент остановит новые входы и напишет об этом. Причины: ручная сделка, другой
советник на этом же счёте, старый magic из прошлой версии конфига.

```powershell
.\.venv\Scripts\python.exe -m mt5_agent status   # смотри блокировки
```

Разберись, чьи это позиции. Если это твои ручные — можно закрыть их в терминале или
поставить `unknown_position_action: "warn"` (не рекомендуется, пока не уверен).

### 4.5 Нужно срочно всё остановить

```powershell
.\.venv\Scripts\python.exe -m mt5_agent kill --reason "причина"
```

Агент закроет свои позиции и остановится. Если процесс уже не работает — просто не
запускай его, пока файл `state/KILL_SWITCH` на месте: `start_agent.ps1` откажется
стартовать. Снимать стоп — только осознанным `unkill`.

### 4.6 VPS перезагрузился (обновление Windows)

Проверь после загрузки:

```powershell
Get-ScheduledTask -TaskName "MT5-Agent-*" | Format-Table TaskName, State
Get-Content .\state\heartbeat.txt         # обновляется ли
.\.venv\Scripts\python.exe -m mt5_agent status
```

Если задачи выключены (Update их иногда сбивает) — включи:
`Enable-ScheduledTask -TaskName "MT5-Agent-Watchdog"`.

## 5. Переход демо → реал (чек-лист)

- [ ] Демо-период отработан полностью (1–3 месяца, без «докруток» на ходу).
- [ ] Ведётся статистика: число сделок, win rate, средний результат, реальное
      проскальзывание, реальный спред.
- [ ] Расхождение демо и бэктеста объяснено и приемлемо.
- [ ] Открыт **отдельный** реальный счёт; сумма — та, которую можно потерять.
- [ ] Создан отдельный терминал (portable) и заполнены `MT5_REAL_*` в `.env`.
- [ ] `I_UNDERSTAND_REAL_MONEY_RISK=TRUE`, `safety.demo_only: false`, `agent.mode: live`.
- [ ] Уведомления Telegram проверены (и приходят с этого VPS).
- [ ] Первый месяц на реале — минимальный допустимый лот/риск, наблюдение каждый день.
- [ ] Раз в неделю — сверка из п. 3, раз в месяц — пересмотр параметров риска.

## 6. Обновление кода

```powershell
# 1. Остановить агента и зафиксировать, что позиции закрыты или защищены стопами
.\.venv\Scripts\python.exe -m mt5_agent status

# 2. Обновить код (git) и зависимости
git pull
.\.venv\Scripts\python.exe -m pip install -r requirements.txt

# 3. Прогнать тесты — они не требуют ни Windows, ни интернета
.\.venv\Scripts\python.exe -m pytest -q

# 4. Проверить окружение и вернуться к работе
.\.venv\Scripts\python.exe -m mt5_agent check
.\scripts\start_agent.ps1 -Mode paper
```

Правило: **не менять логику риск-модуля и исполнения в один день с переходом на
реальные деньги.** Сначала код, тесты и демо — потом реал.
